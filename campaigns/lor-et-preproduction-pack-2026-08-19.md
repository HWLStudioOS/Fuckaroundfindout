## 3. Creative proof gate

Pass the Baton and Four Decisions share the same project gate. Only the handoff test differs.

### Gate A: the one-project test

All must pass:

1. One named live project and one identifiable workstream, package or issue connects the four roles.
2. One named person per role works on it and describes only the authority they genuinely hold.
3. Each person has one camera-safe proof item: drawing, model, screen, package, order, tracker, check or sign-off.
4. Each person can explain one recent decision and the visible site consequence if it is wrong or late.
5. The project lead confirms the four accounts are real, not a composite invented for filming.
6. Site, screen, document, release and safety clearance owners are named.

If Gate A fails, stop. Do not hide two unrelated projects under either treatment. P10 needs a client-approved copy and structure decision.

### Gate B: the literal handoff test

Pass the Baton also needs three real interfaces. For each interface:

- The upstream person names the output.
- The downstream person independently names the same item as an input.
- The same reference, revision or workflow proves both accounts.
- Both can explain the consequence of a failed or late handoff.
- Both sides can be captured truthfully and safely across the two visits.

### Treatment decision

- Gate A and Gate B pass: use Pass the Baton.
- Gate A passes but Gate B fails: use Four Decisions. Four real decisions on the same project, with no staged direct causality.
- Gate A fails: no automatic fallback. Harrison and LOR decide new P10 wording before cameras roll.

Capture decision-safe coverage on both visits even if the Baton passes. Do not spend the day forcing a physical prop or a false handoff.
